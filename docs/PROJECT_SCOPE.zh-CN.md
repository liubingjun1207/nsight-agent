# Nsight Agent 最终范围与完成标准

范围确定日期：2026-10-12。v1.0 完成已有报告分析基线；同日用户明确批准以下 v1.1 有限补充，完成后再次进入维护阶段。

## 项目目标

让深度学习/CUDA 工程师在 Codex 中，通过自然语言调用本地 Nsight，受控采集 Systems 任务、分析已有报告和已记录的 eager 算子关联，并可选读取 Compute 指标，获得可复核的结构化证据。

完成标准由能力覆盖与实际调用决定。范围内的问题应有可发现、可调用的工具入口，避免因为服务没有提供相应能力而中断分析。连接失败、版本不支持和报告缺少数据应有明确诊断，不生成虚构的统计值。

本项目不承诺任意提问都能得到数字，也不承诺模型对所有自然语言表达都选择相同工具。验收验证指定问题的实际 Codex 工具调用，并检查服务的完整能力覆盖。

## 固定的产品边界

| 项目 | 最终范围 |
| --- | --- |
| 产品形态 | 本地 Python MCP 服务、STDIO 接入 Codex，附分析 skill、示例和文档 |
| 使用场景 | Windows/Linux 服务主机本地分析；Systems 采集只启动预登记的本地任务，平台证据见 v1.1 验证记录 |
| 输入 | `.nsys-rep`、Nsight 导出的 SQLite；可选 `.ncu-rep` |
| 分析引擎 | 本机 Nsight Systems 官方统计、可选 Compute 官方 CSV 导入；服务转换参数、整理表格和比较结果 |
| 已验证基线 | Nsight Systems 2025.6.3；Python 3.11/3.13 的无 GPU CI与真实 Windows 集成验证 |
| 输出 | 结构化结果、单位、筛选条件、版本、复核命令、分页信息，以及 Markdown/JSON 证据导出 |
| 分发 | GitHub 开源代码、wheel、完整源码包、公开样例、许可证和校验文件 |

成功查询的前置条件是：Codex 已启用并连接服务，本机安装兼容 Nsight，报告可读取并包含所需事件。分析既有报告不要求本机 GPU。其他 Nsight 版本按实际报告/选项支持情况返回能力状态，不承诺所有版本兼容。

## 固定的分析覆盖：18 个官方报告

以下列表取自本机 Nsight Systems 2025.6.3 的实际能力发现结果。它是 Systems 的最终统计清单；以后 Nsight 新增报告不自动扩大项目范围。

| 能力组 | 官方报告 |
| --- | --- |
| CUDA API 汇总、明细与关联汇总 | `cuda_api_sum`、`cuda_api_trace`、`cuda_api_gpu_sum` |
| Kernel 汇总与启动配置分组 | `cuda_gpu_kern_sum`、`cuda_gpu_kern_gb_sum` |
| GPU kernel/内存操作汇总与明细 | `cuda_gpu_sum`、`cuda_gpu_trace` |
| 内存操作耗时与字节数 | `cuda_gpu_mem_time_sum`、`cuda_gpu_mem_size_sum` |
| Kernel 发射、排队与执行 | `cuda_kern_exec_sum`、`cuda_kern_exec_trace` |
| NVTX 总汇总、Push/Pop 汇总与明细、Start/End 汇总 | `nvtx_sum`、`nvtx_pushpop_sum`、`nvtx_pushpop_trace`、`nvtx_startend_sum` |
| NVTX GPU 投影汇总与明细 | `nvtx_gpu_proj_sum`、`nvtx_gpu_proj_trace` |
| NVTX 范围与 kernel 关联统计 | `nvtx_kern_sum` |

报告覆盖不等于所有 Nsight CLI 命令及选项的覆盖。范围包括各报告明确支持的内置名称显示参数、名称筛选、排序、分页，以及 Nsight 支持的时间/NVTX 筛选；不开放自定义统计脚本或任意命令。

能力发现应区分本机安装的报告、服务允许调用的报告和实际缺失的能力。保留 v0.2 的专用工具，为上述白名单提供统一的统计调用入口，使 Codex 在专用工具不足时仍能调用相应官方统计。无需为每种提问增加新工具。

v0.2 覆盖其中 7 个报告；v1.0 的统一入口补齐剩余 11 个，保留比较和导出能力。实际验收证据见 [验证记录](VALIDATION.md) 与 [模型调用汇总](evaluation-results.json)。

## 完整调用链路

1. 安装后检查运行环境，并执行真实 MCP 握手、工具发现和工具调用；配置已写入不等于服务已连接。
2. Codex 可发现当前支持的统计能力、参数和限制，再打开本地报告。
3. 用户提出范围内问题时，Codex 选择专用工具或统一统计入口，调用 Nsight 并返回证据。
4. 名称、时间、NVTX 范围和分页控制支持继续查询。原始报告保持不变。
5. 两份报告对比沿用 v0.2 的 kernel/API/内存四类汇总；不要求所有新增报告都支持对比。
6. 分析结果可导出；会话 ID、缓存、超时和错误行为均可诊断。

错误至少区分：服务未连接、Nsight 未找到、报告/选项不支持、路径或报告无效、缺少采集数据、无匹配结果、失效 ID、命令失败及超时。可以重试的错误给出可执行的恢复步骤，不以错误结果代替测量。

统计解释保持边界：CPU API 时间、GPU 执行时间与应用经过时间分开；累计时间不解释为利用率；排队时间不是自动的瓶颈判定；NVTX GPU 投影采用官方关联语义及其线程限制。没有 Start/End 单次官方明细报告时，明确保留该限制。

## 不纳入本项目

- GUI 自动操作、截图识别、独立桌面界面或自建可视化分析平台。
- Compute 自动采集、Graphics、MPI/OpenMP、图形 API 等其他统计领域。
- 远程采集、训练作业调度、SSH、集群或多机管理。
- 未标注报告、编译/融合图的完整 PyTorch 自动归因、kernel 融合/重命名的自动配对、自动根因结论。
- 修改训练代码、自动调参、自动运行优化实验或承诺性能收益。
- 原始数据库 SQL 分析引擎、任意 shell/统计脚本接口。
- 所有 MCP 客户端、所有操作系统、所有 Nsight 版本的全面认证。

缓存仅在现有超时/稳定性要求无法满足时作为必要实现手段；速度排名、无限规模报告支持和持续性能优化不构成封版门槛。

## v1.0 的有限验收清单

以下是固定发布门槛，完成证据分别记录在验证文档、GitHub Actions 与 Release 中。

验收分三层，分别留存证据：

1. **稳定完成分析流程**：安装提供分析 skill 和清晰工具说明；模型先发现能力、打开报告，再筛选、复核和导出。专用工具不足时使用统一入口，缺少数据时说明原因。范围内的工具覆盖与模型的选择行为分别验证。
2. **验证真实使用效果**：用固定自然语言问题驱动已登录 Codex，记录实际 MCP 调用、参数、结果及最终回答；检查关键数值、范围选择和失败处理。代表性流程重复运行，公布实际通过次数、模型/客户端环境和限制。SDK 测试通过不能替代这层。
3. **打通安装发布体验**：从发布 wheel/源码包在新环境安装，执行环境检查、真实连接检查、Codex 配置、skill 安装和样例分析；完成升级/卸载说明及可下载发布资产。只在对应证据齐全后标记完成。

自然语言验证使用公开报告；登录状态、原始会话日志保留在本地，不提交凭据。发布记录提供汇总和复现方式，不宣称所有模型、所有表达的成功率为 100%。

- 18 个报告均有受控调用入口、参数说明和能力检测；可用/不可用状态与本机实际能力一致。
- 每个报告的列、单位、参数转发和错误路径有测试；有真实数据时核对官方输出，缺少事件时验证明确诊断。
- Windows 对公开 Linux 报告的真实集成通过；需要补充的事件样例注明采集平台、来源与许可。
- 从干净环境安装发布包，实际完成 Codex 的连接、工具发现及分析流程。
- 固定的自然语言验收场景成功调用工具：最耗时 kernel、单次 kernel、grid/block 分组、API 汇总/明细、内存汇总/明细、发射/排队、NVTX 发现与 GPU 投影、按范围统计、双报告对比和证据导出。
- 对缺少数据、无匹配、无效路径、版本不支持、超时和失效 ID，返回预期诊断，不虚构数字。
- 原有 v0.2 接口、公开演示、Windows/Linux CI、源码包和 wheel 均通过对应检查。
- 文档准确列出实际能力及限制，发布包和校验文件可下载。

v1.0 已按上述清单完成并发布；历史记录不扩大为 v1.1 的验证证据。

## v1.1 的有限补充与结束条件

用户确认“方便”的实际使用差距后，批准以下四项，不再增加其他分析领域：

1. **Linux 本地运行**：Linux 安装脚本、真实官方阅读器和 MCP 验证；注明验证发行版、容器/WSL、Python、Nsight 和 GPU，不声称所有 Linux 环境认证。
2. **受控 Systems 采集**：用户维护 TOML 任务登记；工具仅接受任务名，固定 CUDA/NVTX 参数、时长/超时上限、独立输出和失败不注册。无 SSH、集群任务、任意命令/参数入口。
3. **已记录的 eager 算子关联**：提供 emit_nvtx 示例与 `nvtx_kern_sum` 便捷工具，保留原标签和启动关联语义；无历史报告自动补标注、编译/融合图完整归因或训练代码自动改写。
4. **可选 Compute 阅读器**：官方 `.ncu-rep` CSV 导入，固定 occupancy/throughput/memory/stalls/launch 五组、指标白名单、版本/缺失值/单位/分页及导出。不开任意指标、section、脚本或 ncu 自动采集入口。

新增六个工具，合计十八个；原来的十二个工具和十八个 Systems 报告保持兼容。流程以“本地受控采集 → Systems 热点 → 已标注 NVTX 算子关联 → 可选 Compute 查询 → 导出”收敛。

结束条件：新增工具的参数边界、失败处理与无 GPU 测试通过；Linux 有真实阅读/采集/MCP 证据；eager 标注和五个 Compute 指标组与官方输出核对；真实 Codex 调用新增流程；Windows/Linux 包安装与连接检查通过；文档列出实际环境和限制。记录见 [扩展指南](EXTENSIONS.zh-CN.md) 与 [v1.1 验证](VALIDATION-v1.1.md)。

以上清单完成后进入维护阶段，只处理范围内的正确性、安全、必要兼容性与文档错误。新增领域、平台全面认证或自动优化仍需另行明确修改范围。

## v1.2 的有限官方诊断补充

2026-10-13 用户批准接入六条官方诊断规则及分析流程。本次只增加 `nsight_analysis_rules` 和 `nsight_analyze`，合计二十个工具；白名单固定为 `cuda_api_sync`、`cuda_memcpy_async`、`cuda_memcpy_sync`、`cuda_memset_sync`、`gpu_gaps`、`gpu_time_util`。

服务继续调用官方命令，复用原报告保护与缓存，不增加原始数据库分析引擎。支持规则发现、版本/参数兼容检查、独立时间或 NVTX 筛选、API 名称筛选、排序、完整规则结果后的分页及证据导出。gap、threshold 和 chunks 有界，不接受自定义规则、脚本、SQL 或输出命令。

完成条件：六条规则的真实输出与直接 CLI 一致；覆盖时间/NVTX、默认与修改阈值、未命中与真实缺失数据；MCP 发现和导出通过；安装后的包及真实 Codex 诊断→明细→导出流程验证；中英文文档和 skill 说明候选证据、重叠过滤、时间与资源利用率差别。验证平台与未覆盖条件见 [v1.2 验证](VALIDATION-v1.2.md)。

本次不增加 UVM/IO 专项、多机通信、远程采集、Compute 自动采集、完整融合归因或自动优化。规则完成后回到既定维护范围，不以六条规则能定位所有根因作为验收条件。
